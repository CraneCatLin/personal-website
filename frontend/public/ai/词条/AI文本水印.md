# 原理、实现、检测与对抗技术  
  
## 核心摘要  
  
AI文本水印通过在文本中嵌入不可见标识，实现对AI生成内容的溯源与认证。技术路线包括生成时水印（如SynthID-Text）、编辑后水印（如PostMark）及语义水印。检测方法分为基于统计学的密钥检测与基于深度学习的模式识别。对抗攻击涵盖同义词替换、翻译转换、生成对抗网络伪造等。当前主流方案在鲁棒性与隐蔽性之间存在权衡，尚无通用抗攻击水印。  
  
## 关键信息提炼  
  
### 1. 水印生成原理与算法  
  
- **生成时水印（白盒）**：在语言模型逐词生成阶段，依据密钥将词汇表划分为“绿灯”与“红灯”集合，通过有倾向性地选择绿灯词，使生成文本的词概率分布偏离自然分布，形成可检测的统计信号。代表方案：Google SynthID-Text、KGW。  
- **编辑后水印（黑盒）**：对已生成文本独立操作，通过语义分析在适当位置插入一组预定义水印词，不依赖模型内部状态。代表方案：PostMark。  
- **语义水印**：将水印信息绑定到句子的语义角色（施事、受事）及语法关系图，利用替换同义词或改述句子后语义结构保持不变的性质实现抗改写。代表方案：PASA。  
- **标点/格式水印**：通过替换全角/半角标点、不可见字符或微调空格编码信息，隐蔽但极易被格式化操作清除。  
  
### 2. 典型实现细节  
  
#### SynthID-Text 采样算法  
- 使用 **Tournament 采样**：多次随机从词汇表中抽取子集，每次选择子集中概率最高的词，最终通过多数投票决定输出词。  
- 采样过程依赖密钥，密钥控制每次子集的划分方式，使生成的词序列具有特定统计模式。  
- 检测时使用相同密钥计算文本中绿灯词出现频率的 $z$ 分数，若 $z$ 超过阈值则判定含水印。  
  
#### PostMark 生成流程  
1. 输入原始文本，使用嵌入模型（如 jina-embeddings-v3）计算每个候选位置的语义向量。  
2. 从秘密水印表中选取与上下文语义最兼容的水印词。  
3. 由语言模型将水印词无缝嵌入到文本中，保持语法与流畅性。  
  
### 3. 检测与识别方法  
  
- **统计学检测**：需要密钥。计算待检文本中属于密钥定义的绿灯词的比率 $p$，与理论均匀分布下的期望 $p_0$ 比较。使用假设检验，检验统计量为  
  
  $$z = \frac{p - p_0}{\sqrt{p_0(1-p_0)/n}}$$  
  其中 $n$ 为文本长度。$z$ 值越大，水印存在置信度越高。  
- **深度学习检测**：使用 BERT、RoBERTa-BiGRU-eKAN 等模型提取文本的多维特征（句长分布、连接词频率、词汇丰富度等），训练分类器区分自然文本与带水印文本。不依赖密钥，但准确率低于统计学检测。  
  
### 4. 对抗攻击与清除技术  
  
- **简单破坏攻击**：同义词替换、标点符号统一化（如半角转全角）、重述（使用另一语言模型改写）。  
- **系统性攻击**：  
  - **生成对抗网络（GAN）**：训练生成器学习去除水印模式。  
  - **Warfare 攻击框架**：同时学习水印的添加与移除，可伪造水印实现错误归因。  
- **翻译转换攻击**：将文本翻译为中间语言（如英语→中文→英语），通过剧烈改变词序与用词破坏统计模式。  
- **工具清除**：针对标点/格式水印，使用 Python 脚本（如 `python-docx`）批量清除文档中的隐藏字符或统一标点。  
  
## 遗留问题或待澄清点  
  
- 语义水印（PASA）在多次重述或摘要操作后，其检测率下降的具体量化指标。  
- 不同水印方案在文本长度极短（如少于 50 个词）时的检测灵敏度下限。  
- 是否存在一种能在白盒攻击（攻击者已知水印算法与密钥）下依然保持安全的文本水印方案。  
  
## 常见误解纠正  
  
- **误解**：文本水印依赖在文件中添加不可见元数据或特殊字符。  
  **纠正**：现代AI文本水印主要通过对词汇选择概率的统计控制实现，不改变文本的可见形式，且可存在于纯文本中。  
- **误解**：任何水印都能被同义词替换或改写完全移除。  
  **纠正**：语义水印（如PASA）将水印绑定于语义角色结构，简单同义词替换不改变核心语义图，水印仍可被检测。  
  
## 专业延伸：性能权衡维度  
  
- **鲁棒性 vs 隐蔽性**：增加水印强度（如更多使用绿灯词）提高检测率，但可能导致文本统计特征异常（如词汇多样性降低），增加被深度学习检测器识别的风险。  
- **抗攻击能力 vs 计算开销**：Tournament 采样需要多次随机子集采样与评分，相比原始贪心解码增加约 $O(k \log k)$ 的时间复杂度（$k$ 为候选集大小），但可抵御多种简单改写攻击。
